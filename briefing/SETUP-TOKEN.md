# 브리핑 전용 장기 토큰 설정 (로그인 풀림 근본 예방)

## 왜

아침 브리핑(및 launchd 루틴)은 지금 **사용자가 평소 쓰는 대화형 claude 로그인(OAuth
세션)을 공유**한다. 그래서 그 세션이 만료되면(예: 2026-08-03 라이선스 갱신으로 풀림)
브리핑도 통째로 죽는다.

`claude setup-token` 으로 발급하는 **장기 인증 토큰**을 브리핑 전용으로 두면, 대화형
로그인이 풀려도 브리핑은 자기 토큰으로 **독립적으로 계속 돈다.** 구독 안에서 추가 비용
없이(= API key 종량과금과 다름) 만료 주기를 크게 늘리는 방법이다.

> 공식 문서 확인(2026-08): 환경변수는 `CLAUDE_CODE_OAUTH_TOKEN`, 토큰 만료는 **1년**,
> 대화형 `/login` 세션과 **완전히 별개 자격증명**이다. (docs: authentication / env-vars)

## 발급 절차 (사용자 1회, 대화형)

1. 터미널에서:
   ```
   claude setup-token
   ```
   `/login` 과 같은 **브라우저 승인 창**이 열린다. 승인하면 **토큰 문자열이 터미널에
   출력**된다(자동 저장 안 됨 — 직접 복사해야 한다).

2. 출력된 토큰을 복사한 뒤, 브리핑 전용 파일에 저장(레포 밖, 권한 600):
   ```
   pbpaste > ~/.config/calendar-worklog/claude-token
   chmod 600 ~/.config/calendar-worklog/claude-token
   ```
   (setup-token 은 브라우저 승인을 낀 대화형이라 `claude setup-token > 파일` 리다이렉트는
   피한다 — 출력이 온전히 안 담길 수 있다. 복사→pbpaste 가 안전.)

3. 끝. `run-briefing.sh` 가 이 파일이 있으면 자동으로 `CLAUDE_CODE_OAUTH_TOKEN` 으로
   주입해 인증한다. 없으면 기존 OAuth 세션으로 폴백한다(하위호환).

> ⚠️ **`--bare` 모드는 이 토큰을 무시**한다(ANTHROPIC_API_KEY 만 읽음). 러너는
> `claude -p`(bare 아님)라 정상 동작한다. 러너에 `--bare` 를 넣지 말 것.

## 검증

```
# 러너가 토큰을 집는지 (dry: 인증 분기만 확인)
grep -A6 CLAUDE_TOKEN_FILE ~/dev/calendar-worklog/briefing/run-briefing.sh

# 실제 1회 실행(실제 브리핑 DM 이 감)
~/dev/calendar-worklog/briefing/run-briefing.sh
grep '^인증:' ~/dev/calendar-worklog/briefing/logs/$(date +%F).log
# → "인증: 브리핑 전용 장기 토큰 사용" 이 보이면 성공
```

인증 라인은 로그 리다이렉트 뒤에 찍히므로 **날짜별 로그에 남는다.** 실행마다 어느
자격증명으로 돌았는지 사후에 확인할 수 있다(전용 토큰인지 대화형 세션 폴백인지).

## 만료되면 (1년 주기)

토큰은 **발급 1년 뒤 만료**된다. 자동 갱신도, 사전 경고도 없다(공식 문서 확인).

- **감지 한계 주의**: `authcheck.py` 는 *대화형 세션*의 자격증명(keychain)만 본다.
  장기 토큰 만료는 거기 안 잡힌다 → **브리핑이 실제 실패할 때 `notify.py` 가 잡아** 폰에
  알린다. 즉 만료 당일 아침 브리핑 실패 알림으로 알게 된다(하루 지연).
  이때 알림 문구는 `/login` 이 아니라 **`setup-token` 재발급 + 파일 교체**를 안내한다
  (전용 토큰 모드에서 `/login` 은 대화형 세션만 고칠 뿐, 죽은 토큰 파일은 다음 실행에서
  또 export 되어 브리핑이 계속 실패하기 때문).
- **선제 대비 권장**: 발급 시 **1년 뒤 캘린더에 "브리핑 토큰 갱신" 일정**을 걸어두면
  만료 전에 재발급할 수 있다.
- 만료됐으면 위 발급 절차를 다시 1회.

> **주의**: 이 토큰은 대화형 로그인과 별개 자격증명이다. 토큰 파일이 유출되면 구독
> 권한이 노출되니 레포 밖·권한 600 을 지킨다. `.gitignore` 로 커밋 방지.
